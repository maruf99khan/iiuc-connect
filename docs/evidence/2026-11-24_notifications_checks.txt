Database (migration 20261124150000_notifications, applied to the hosted project)
  Table notifications (user_id, kind, link, read_at, created_at). A row holds a kind
  and an in-app path only: no names and no free text, so it cannot leak what a member
  typed. The app turns the kind into one sentence.
  Rows are made only by triggers (members have no insert privilege and cannot call
  private.notify):
    mentorship: new request -> mentor; accepted, declined, expired -> mentee;
                cancelled -> the other side (a call with no signed-in user -> mentee)
    jobs:       new application -> poster; shortlisted, rejected -> applicant;
                withdrawn -> poster
  Members can read, mark read (only read_at is writable), and delete their own rows.
  The link must start with / and not with // and is at most 200 characters (CHECK).
